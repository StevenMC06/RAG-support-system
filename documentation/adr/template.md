# ADR-XXX: <short, decision-oriented title>

**Status:** Proposed | Accepted | Superseded by ADR-YYY | Deprecated

## Context

What situation forced this decision? What constraints (learning goals, cost,
time, existing infrastructure) were in play?

## Decision

What did we actually decide to do? State it plainly, in one or two sentences.
Add a short code/diagram block only if it clarifies the shape of the decision.

## Rationale

Why this, specifically? Bullet points are fine.

## Alternatives considered

What else did we look at, and why was it rejected or deferred? Naming the
rejected option prevents re-litigating it later without a new reason.

## Consequences

What does this decision cost us, or what follow-up work does it create?
Known trade-offs and deferred work belong here, not hidden in code comments.

## Revisit when

The concrete condition that should trigger a re-read of this ADR — a scale
threshold, a new requirement, a deprecation. "Never" and "always" are both
valid answers if that's genuinely true.
